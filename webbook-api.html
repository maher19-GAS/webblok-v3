Quick Start

To add a new book to the WebBook reader, follow these steps:

  1. 1
    Create the book folderPlace all .md chapter files in a folder, e.g. book/
  2. 2
    Register files in BOOK_CONFIGAdd each file with its path, part label, and unique id
  3. 3
    Open webbook-v2.html in a browserFiles are fetched at runtime via fetch() — no build step needed
  4. 4
    Content is auto-split into slides120–170 words on mobile, 450–550 on desktop. Each slide gets a component type automatically.
js — BOOK_CONFIG file registration
const BOOK_CONFIG = {
  title: 'My Book Title',
  files: [
    { path: 'book/prologue.md',   part: 'Introduction', id: 'prologue' },
    { path: 'book/chapter-01.md', part: 'Part One',     id: 'ch01'     },
    { path: 'book/chapter-02.md', part: 'Part One',     id: 'ch02'     },
  ],
  mobileWords:  { min: 120, max: 170 },  // words per slide on mobile
  desktopWords: { min: 450, max: 550 },  // words per slide on desktop
  wpm: 200,          // reading speed estimate
  dbName: 'mybook_db', // IndexedDB database name
  dbVersion: 2,
};

💡 Naming Conventions

Use kebab-case filenames. You can combine multiple chapters in one file (e.g. chapters-03-04.md). Files are loaded in the order declared in BOOK_CONFIG.files.

Markdown Format

WebBook v2 parses a rich subset of Markdown. Use standard CommonMark syntax plus these extensions:

Headings

markdown — heading levels

## H2 — Chapter title (always starts a new slide, detected as chapter type)
### H3 — Section heading (may start new slide if enough words accumulated)
#### H4 — Sub-section heading (stays inline in current slide)

Slide Component Types

Each slide is automatically classified into one of 9 component types based on its block content. Each type has a distinct visual style, glow color, and badge.

cover
Book cover / title page. First slide is always cover.
Always slide index 0
chapter
Chapter opener with large number and title.
H1/H2 with keywords: الفصل | الجزء
quote
Highlighted blockquotes or Quranic verses.
> blockquote or ﴿﴾ in text
science
Scientific content with stages, principles, models.
Keywords: معادلة | مراحل | طبقات
equation
Mathematical formulas, code blocks, equations.
```fenced code block```
table
Comparison tables, data grids. Always own slide.
| table | syntax |
list
Bullet or numbered lists with 3+ items.
- item (3+ items)
prose
Regular narrative paragraphs. Default fallback type.
Default — no special trigger
cta
Call-to-action. Adds actionable buttons automatically.
Keywords: اشترك | 2030B.com | انضم

🎯 Classifier Priority Order

cover (index 0) → table → equation (code block) → quote → chapter (H1/H2 with keyword) → list (3+ items) → science (keywords) → cta (keywords) → prose (default)

parseMD(md: string) → Block[]

Parses a Markdown string into an array of typed block objects. Handles all block types including Quranic verse detection and complex table parsing.

js — parseMD usage
const md = `## Chapter 1
      
First paragraph of the chapter.

- List item 1
- List item 2

| Col A | Col B |
|-------|-------|
| Val 1 | Val 2 |
`;

const blocks = parseMD(md);
// Returns:
[
  { type: 'heading', level: 2, text: 'Chapter 1' },
  { type: 'para', text: 'First paragraph...' },
  { type: 'list', items: ['List item 1', 'List item 2'] },
  { type: 'table', rows: [
    { isHeader: true,  cells: ['Col A', 'Col B'] },
    { isHeader: false, cells: ['Val 1', 'Val 2'] },
  ]},
]

classifyBlocks(blocks: Block[], slideIndex: number) → string

Classifies a group of blocks into a slide component type. Uses a priority-ordered ruleset based on block types and Arabic keyword detection.

js — classification logic (priority order)
function classifyBlocks(blocks, gIdx) {
  if (gIdx === 0) return 'cover';          // 1. First slide is always cover
  if (hasTable)   return 'table';          // 2. Has Markdown table
  if (hasCode)    return 'equation';       // 3. Has fenced code block
  if (hasQuote || hasQuran) return 'quote'; // 4. Blockquote or ﴿﴾
  if (hasH1H2 && chapterKeyword) return 'chapter'; // 5. Chapter heading
  if (hasList3plus) return 'list';         // 6. List with 3+ items
  if (scienceKeywords) return 'science';   // 7. Science/tech keywords
  if (ctaKeywords) return 'cta';           // 8. Call-to-action keywords
  return 'prose';                           // 9. Default
}

Annotation System

Users can annotate any selected text with 4 types of annotations: Notes, Bookmarks, Comments, and Shares.

Annotation Flow

  1. 1
    User selects textWorks on desktop (mouseup) and mobile (touchend + selectionchange). Minimum 3 characters.
  2. 2
    Tooltip menu appearsPositioned above (or below if near top) the selection with Note, Bookmark, Comment, Share buttons.
  3. 3
    User picks an actionA highlight <span> is injected wrapping the selected text. An IndexedDB record is created.
  4. 4
    Annotation storedRecord includes selected text, note text, slide index, highlight ID, and timestamp.
  5. 5
    Clicking a highlightOpens the corresponding aside panel and scrolls to the annotation card.

Text Selection API

The selection tooltip menu handles both desktop and mobile selection events, working around the native mobile text menu.

⚠️ Mobile Behavior Note

Mobile browsers show their own copy/paste menu when text is selected. The WebBook tooltip is positioned via fixed coordinates and uses selectionchange + touchend events with a 200ms delay to appear after the native menu. Using mousedown with preventDefault() on the tooltip buttons prevents the selection from being cleared when tapping a button.

SELECTION_STATE Object

let SELECTION_STATE = {
