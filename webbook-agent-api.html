Webbook MD Structure API

Complete reference for authoring books as Markdown files that the Webbook reader renders as beautiful interactive slides. This document covers every supported block type, all 9 slide classifications, extended slide types (charts, media, statistics), word-count splitting rules, and complete AI prompts for generating well-structured book chapters.

Scope: This API describes the Markdown book structure only — not the Webbook runtime (IndexedDB, annotations, navigation). Authors and AI agents use this reference to write correctly structured .md files that the reader can split, classify, and render.

# How Markdown becomes slides

The reader processes each .md file through four stages:

StageFunctionInput → Output
1. ParseparseMD()Raw MD string → array of typed blocks
2. Splitsplit()Blocks → array of slides (each ≤ word limit)
3. Classifyclassify()Slide blocks → slide type string (cover, chapter, prose…)
4. RenderbuildSlide()Slide data → interactive DOM element
Key insight: You don't control slide boundaries manually. The parser infers them from heading levels, --- separators, and word count limits. Write naturally — the reader handles pagination.

# Slide Types (9 core)

Each slide is automatically classified by examining its blocks. The classifier runs in order — first match wins:

1coverGlobal index = 0 (first slide of the book)indigo
2tableAny table block presentblue
3equationAny code block presentviolet
4quoteAny quote block, or text contains ﴿…﴾gold
5chapterh1/h2 whose text matches الفصل / المقدمة / الخاتمة…purple
6listList block with ≥3 itemsgreen
7scienceText matches: معادلة / مراحل / خوارزمية / مبدأ…teal

# Word Count Splitting Rules

DeviceMin wordsMax wordsReasoning
Mobile (<768px)120170Short slides — one screen, thumb-scroll friendly
Desktop (≥768px)450550Longer slides — reading comfort on large screens

Splitting rules (in priority order):

  1. h1/h2 heading → always flush current slide, start new one
  2. h3 heading → flush current slide only if current word count ≥ min
  3. h4 heading → always stays in current slide
  4. HR (---) → flush current slide if word count ≥ min
  5. Table or code block → flush current slide, render block alone, then flush again
  6. Any block that would push total past max → flush first, then add block
  7. Any block that pushes total past max → flush immediately after adding
Tables and code blocks always occupy their own slide. The parser flushes before and after them. Don't try to put other content in the same MD section expecting it to merge.

# Complete Chapter Template

Copy this template for each new chapter. Fill in all sections. The parser handles the rest.
chapter-XX.md — full template 
=== CHAPTER OPENER (h2 + keywords = chapter slide) ===
## الفصل الثاني: اسم الفصل هنا

جملة تشويقية قصيرة تُلخّص جوهر الفصل
وتُشعل فضول القارئ للمتابعة.

---

=== OPENING QUOTE (quote slide) ===
> *اقتباس ملهم يرتبط بموضوع الفصل* — اسم المؤلف

---

=== FIRST SECTION (prose slide) ===
### العنوان الفرعي الأول

فقرة تُقدّم المفهوم الرئيسي مع أمثلة من الحياة اليومية.
استخدم **النص الغامق** للمصطلحات الأساسية و*الإيطالي* للتأكيد.

فقرة ثانية تُعمّق الفكرة مع ربطها بالسياق العام.

---

=== KEY POINTS (list slide — 3+ items trigger list type) ===
### النقاط الجوهرية

- النقطة الأولى: وصف موجز ومباشر
- النقطة الثانية: وصف موجز ومباشر
- النقطة الثالثة: وصف موجز ومباشر

| العنصر      | الوضع الحالي | بعد التطبيق |
|------------|------------|------------|
| التركيز    | منخفض       | عالٍ ✓      |
| الطاقة     | متذبذب      | مستقر ✓     |
| الإنتاج    | ضعيف        | مرتفع ✓     |

---

=== FORMULA / FRAMEWORK (equation slide) ===
### الصيغة الجوهرية

```
معادلة التحوّل:

  وعي + نظام + استمرارية = تغيير حقيقي

المتغيرات:
  وعي       = فهم جذور المشكلة
  نظام      = روتين يومي مُصمَّم بعناية
  استمرارية = التزام لا يقل عن 21 يومًا
```

---

=== QURANIC VERSE (auto-detected = quote slide) ===

﴿إِنَّ اللَّهَ لَا يُغَيِّرُ مَا بِقَوْمٍ حَتَّى يُغَيِّرُوا مَا بِأَنفُسِهِمْ﴾
(الرعد: 11)

---

=== SCIENCE / FRAMEWORK (science slide — keyword triggers) ===
### نموذج المعمار المعرفي

يقوم النموذج على ثلاث طبقات في مبدأ التغيير المتسلسل:
الطبقة الأولى هي طبقة الوعي، والثانية طبقة التخطيط،
والثالثة خوارزمية التنفيذ اليومي.

**المعمار الكامل** يعمل كمنظومة متكاملة لا كعناصر منفصلة.

---

=== SECOND SECTION (prose slide) ===
### العنوان الفرعي الثاني

محتوى الفقرة الرئيسية هنا. اجعل كل فقرة تُضيف
فكرة واحدة جديدة وتنتهي بجملة تُهيّئ للفقرة التالية.

استمر بإضافة الفقرات حتى تصل لحد الكلمات المناسب
(120-170 كلمة على الجوال، 450-550 على سطح المكتب).

---

=== CHAPTER CLOSE / TRANSITION ===
### خلاصة الفصل

في هذا الفصل اكتشفنا أن...
**الفكرة الرئيسية:** جملة تُلخّص الدرس.
**الخطوة التالية:** ما يجب على القارئ فعله الآن.

# AI Prompts for Book Generation

System prompt — book author agent

system prompt 
You are an expert Arabic book author and educational content designer
specializing in self-development, AI literacy, and productivity.

You write in Modern Standard Arabic (MSA) with an engaging, warm tone
that combines academic depth with accessible storytelling.

Your books are rendered in the Webbook reader as interactive slides.
Follow these STRICT Markdown rules when generating chapters:

HEADINGS:
  ## Chapter Title  → new slide, chapter type (use: الفصل / المقدمة / الخاتمة)
  ### Section       → new slide if ≥120 words accumulated, else stays
  #### Sub-point    → always stays in current slide

SLIDE BOUNDARIES:
  Use --- to force a slide break between sections.
  Tables (|...|) and code fences (```) always occupy their own slide.

SLIDE TYPES (auto-classified):
  • cover     → first slide of the book automatically
  • chapter   → h2 with الفصل/المقدمة/الخاتمة keyword
  • quote     → > blockquote OR ﴿...﴾ Quranic verse
  • list      → list with ≥3 items (use for key takeaways)
  • table     → | pipe | table |
  • equation  → ``` fenced block (formulas, frameworks, algorithms)
  • science   → prose mentioning: معادلة/مراحل/خوارزمية/مبدأ/طبقات/نموذج/معمار
